# Database Sequence Migration & Governance Skill

This skill governs the end-to-end migration of primary key generation strategies across the TaskPilot platform from `GenerationType.IDENTITY` to dedicated `GenerationType.SEQUENCE` generators in PostgreSQL and Spring Data JPA.

---

## 🏛️ Core Architectural Invariants (Non-Negotiable)

1. **Zero Data Loss & Sequence Continuity**:
   - Every migrated sequence must initialize with `setval('<seq_name>', COALESCE((SELECT MAX(id) FROM <table_name>), 1))` to guarantee that future generated IDs never collide with pre-existing primary keys.
   - For fresh databases, sequence starting values must default to `1`.

2. **Explicit Per-Table Sequences**:
   - Each database table must own its own discrete sequence named strictly as `<table_name>_id_seq` (e.g. `users_id_seq`, `tasks_id_seq`, `projects_id_seq`).
   - Tables must never share global or cross-table sequence generators, preventing unnatural ID coupling and contention across bounded contexts.

3. **Allocation Size & Increment Synchronization**:
   - For standard OLTP transactional integrity and compatibility with direct SQL inserts / Flyway seed data, sequence definitions must maintain strict synchronization:
     - Hibernate `@SequenceGenerator(allocationSize = 1)` matches PostgreSQL `INCREMENT BY 1`.
     - Where bulk insert batching is explicitly tuned (`allocationSize = 50`), PostgreSQL sequence must be configured with `INCREMENT BY 50` to eliminate ID calculation desynchronization.
     - Default setting for standard entities: `allocationSize = 1` for zero-gap consistency with external tooling, with batching optimization ready.

4. **Flyway Migration Forward-Safety**:
   - Existing tables created with `GENERATED BY DEFAULT AS IDENTITY` or `BIGSERIAL` must be cleanly transitioned via idempotent DDL (`ALTER TABLE ... ALTER COLUMN id DROP IDENTITY IF EXISTS;`, `CREATE SEQUENCE IF NOT EXISTS ...;`, `ALTER TABLE ... ALTER COLUMN id SET DEFAULT nextval('...');`, `ALTER SEQUENCE ... OWNED BY ...`).
   - No historical migration files (`V1`–`V21`) may be altered; all changes must be encapsulated in subsequent versioned migrations (`V22__migrate_identity_to_sequences.sql`).

5. **Entity Hierarchy Cleanliness**:
   - Base audit properties (`createdAt`, `updatedAt`) must remain centralized in `BaseEntity` / `BaseAuditEntity`.
   - Each concrete entity maps its `@Id` and `@SequenceGenerator` explicitly to its dedicated table sequence, preventing inheritance annotation conflicts.

6. **100% Test & Regression Parity**:
   - Full test suites across all modules (`taskpilot-users`, `taskpilot-projects`, `taskpilot-ai`, `taskpilot-infrastructure`, `taskpilot-app`) must pass cleanly without entity mapping exceptions or constraint violations.
